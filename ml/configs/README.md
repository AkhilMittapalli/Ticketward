# ml/configs/

Versioned YAML configs. Pydantic models validate every file on load; a changed config is a
new version (a new file or a bumped `version`), never a silent edit of one already used for a
published dataset or run.

| File | Purpose | Phase |
|---|---|---|
| `datagen.yaml` | generator families and hosts: Family A `openai/gpt-oss-120b` on DeepInfra (Groq fallback); Family B `deepseek-ai/DeepSeek-V3.2` on DeepInfra, served in fp4 (D-07; Mistral La Plateforme is a documented, config-only alternative). Per-host `seed_param` and `quantization`, exact-name model patterns, request parameters, retry policy, $15 budget, terms snapshot | P1 |
| `datagen_prices.v1.yaml` | dated per-million-token prices (as of 2026-09-27) for token accounting and the budget cap; DeepSeek-V3.2 on DeepInfra $0.26 in / $0.38 out ($0.13 cached, informational); the Mistral row is kept for the alternative | P1 |
| `leakage.yaml` | leakage checks C1-C7: thresholds, LSH parameters (asserted b=30, r=4), embedding model, KB and protected-string settings | P1 |
| `rules_baseline.v1.yaml` | E1 rules baseline: keyword -> intent table, lexicon and error-code votes, product-area cues, priority, churn-ultimatum and sentiment cues; hashed into the E1 system id; revise on val only | P2 |
| `bakeoff.yaml` | E3 zero-shot bake-off (spec §9.5, A-02): the seven candidates (five + two optional; Qwen2.5-3B dropped), each with its HF repo (pinned SHA or `<verify>`), license and Lic, size class and fine-tune method, local Ollama model `tw-bakeoff-<id>` and prompt format; the raw `/api/generate` protocol (temperature 0, `num_ctx` 8192, `num_predict` 512, seed 42, `truncate: false`), the CPU sample options and the score weights. Validated by `tw_ml.eval.bakeoff_config` | P2 |
| `prompt_formats/<id>.json` | per-candidate chat template as strings (`prompt_format.v1`, spec §9.4), generated by `python -m tw_ml.export.prompt_format` where Transformers is available; not generated yet | P2 |

Planned (P3): `sft_qwen35_2b.yaml`, `sft_qwen3_1p7b.yaml`, `sft_qwen3_4b_2507.yaml`,
`encoder_modernbert.yaml`. Base model names and revisions are chosen by the P2 bake-off
(ADR-0011) and pinned by HF revision SHA; the `config_sha` of each run is logged to MLflow (spec
§9.5-§9.6).

## Bake-off artifacts (owner steps before `python -m tw_ml.eval.bakeoff run`)

Every candidate runs from a GGUF converted from the official safetensors, never from an Ollama
library tag or a third-party GGUF (mixed quantization levels, supply-chain risk R-12). Per
candidate, on a machine with the pinned tools (verify the versions first):

1. **Pin the repo.** Record the commit SHA of `hf_repo` as `hf_revision` (Llama 3.2 is gated:
   accept its license on HF first).
2. **Convert with the llama.cpp build Ollama ships** (`LLAMA_CPP_VERSION`, b11081 for Ollama
   v0.34.4), text weights only, BF16 then `Q4_K_M` without an imatrix so every candidate is
   treated alike:

   ```bash
   git clone --depth 1 --branch b11081 https://github.com/ggml-org/llama.cpp && cd llama.cpp
   python convert_hf_to_gguf.py <snapshot-dir> --outtype bf16 --outfile ../gguf/<id>-BF16.gguf
   ./build/bin/llama-quantize ../gguf/<id>-BF16.gguf ../gguf/<id>-Q4_K_M.gguf Q4_K_M
   sha256sum ../gguf/<id>-*.gguf
   ```

   Qwen3.5 checkpoints are vision-language: convert the text-only `Qwen3_5ForCausalLM` weights
   and check that no `v.*`/`mm.*` tensors remain.
3. **Create the local model** from a Modelfile that points at the file (the bake-off sends raw
   prompts, so no `TEMPLATE` is needed; request options override `PARAMETER`s):

   ```text
   FROM ./gguf/<id>-Q4_K_M.gguf
   REQUIRES 0.34.4
   ```

   `ollama create tw-bakeoff-<id> -f Modelfile.<id>`, then record the digest that `ollama list`
   (or `GET /api/tags`) reports as `ollama_digest`.
4. **Generate the prompt format** (Transformers via `uv sync --group train` or a Kaggle/Colab
   session; tokenizer files only, no remote code):
   `python -m tw_ml.export.prompt_format --model <hf_repo> --revision <sha> --out ../ml/configs/prompt_formats/<id>.json`.
   For Llama, confirm `runtime_adds_bos` against the GGUF's `tokenizer.ggml.add_bos_token`.
5. **Mark it verified**: set `verify_before_run: false`. The runner's preflight then checks the
   Ollama version, the model's presence, `Q4_K_M` and the digest, and the prompt format's
   goldens, base model and revision; it never pulls or creates a model.

Run order (P2, val + `hard_dev` only; sealed splits are always refused):
`run` (accuracy, all val items; `run --unconstrained` adds the E3 row without the grammar, §9.4)
-> `run --mode cpu-sample` on the dev laptop (50 tickets, `num_gpu 0`, `num_thread 8`: the early
M-08 check) -> `make eval-bakeoff` (reports) ->
`rank` (the §9.5 score and the >= 3-point size rule, `evals/reports/<date>/bakeoff_ranking.json`)
-> 1-epoch probe of the top 2 -> ADR-0011. Outputs go to `evals/runs/bakeoff/`, which must stay
out of git (model outputs quote val tickets).

Secrets never live here: API keys come from `TW_DATAGEN_{A,B}_API_KEY` or the OS credential
store (`python -m tw_ml.datagen keys set`); one DeepInfra key serves both families.
